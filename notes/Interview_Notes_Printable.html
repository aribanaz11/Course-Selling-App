⚡ Lumina Learn — Interview Notes

Full-Stack Project Architecture, File Guide & Interview Cheat-Sheet

🎯 1. The 60-Second Interview Elevator Pitch

"I built Lumina Learn, a full-stack EdTech course selling marketplace and LMS. On the backend, it uses Node.js and Express with a dual-secret JWT Role-Based Access Control (RBAC) system separating students and instructors. I engineered a resilient hybrid data layer using Mongoose with an automatic in-memory fallback that allows zero-downtime execution without local database dependencies. On the frontend, I crafted a dark-mode glassmorphic SPA in HTML5, Vanilla CSS, and JavaScript with multi-filtering, video curriculum players, progress tracking, and creator analytics. The project includes an automated 13-point test suite and Docker containerization."

📂 2. Folder-by-Folder Technical Breakdown

📄 config.js

Loads .env with dotenv. Centralizes port numbers, MongoDB connection strings, and user/admin JWT secret keys.

📄 db.js

Defines 5 Mongoose schemas (User, Admin, Course, Purchase, Review). Contains the Universal Query Layer and in-memory mock fallback engine.

📄 index.js

Main Express application entry point. Mounts middlewares (CORS, JSON), static file serving (/public), REST API routes, and SPA fallback.

🛡️ /middleware

user.js and admin.js handle cryptographic token verification, header parsing, and attaching identity payloads (req.userId, req.adminId).

📡 /routes

user.js (auth, profile, progress), course.js (catalog, purchase, reviews), and admin.js (analytics, course CRUD).

💻 /public (SPA Frontend)

index.html (views & modals), styles.css (design system & dark theme), api.js (state & fetch client), and app.js (DOM controller).

📐 3. Key Architectural Highlights

  • Dual-Secret JWT Security: Student tokens are signed with JWT_USER_PASSWORD while Admin tokens use JWT_ADMIN_PASSWORD. Prevents signature spoofing and privilege escalation.
  • Bcrypt Password Hashing: Salt rounds = 10. Defends against rainbow tables and brute-force cracking.
  • Progress Calculation Formula: (Completed Lessons / Total Lessons) * 100 calculated dynamically per purchase record.
  • Graceful Database Fallback: Catches MongoDB timeouts (2s) and transparently switches to the in-memory engine pre-seeded with realistic data.

💡 4. High-Yield Interview Questions & Answers

Q1: Why did you separate student and instructor JWT secrets?
"Separating secrets provides cryptographic privilege separation. Even if a student modifies their token payload to say role: admin, the signature will fail verification against the admin secret. This stops privilege escalation at the signature level rather than relying solely on payload claims."
Q2: How does the in-memory fallback layer work in db.js?
"On server startup, connectDB() tries to connect to MongoDB with a 2000ms timeout. If unreachable, an internal flag isConnectedToMongo remains false, and our universal query layer routes all database queries to an in-memory mock store pre-seeded with courses and accounts."
Q3: How do you handle Single Page Application (SPA) routing in Express?
"Express serves API routes under /api/*. For any other web route, a wildcard route app.get('*') returns public/index.html. This allows client-side JavaScript to control view transitions without returning 404 on page reload."
Q4: How would you scale this application to handle 100k+ concurrent users?
"1. Horizontal scaling with Docker containers behind an NGINX / ALB load balancer (since JWT auth is completely stateless). 2. Add compound indexes on MongoDB collections (e.g. userId + courseId on Purchases). 3. Implement Redis caching for course preview endpoints. 4. Stream videos via Cloudflare R2 / AWS S3 + CDN."
